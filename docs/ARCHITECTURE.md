# VulnGym Evidence 架构

产品围绕一条可核查的报告声明组织证据。用户先确认要核查的说法，再读取固定 Git 提交中的源码，最后给出与证据对应的结论。

## 处理链

1. **连接项目**：检查本地 Git 仓库，把分支或标签固定为完整 SHA。
2. **提取声明**：从报告中提取文件、行范围、引用代码和待核查说法，保留原文归属。
3. **用户确认**：在工作台逐条检查候选，选择本次复核范围。
4. **读取证据**：使用只读 Git 操作读取指定版本源码，核对引用并提供上下文。
5. **语义复核**：通过所配置的模型进行主审与复核，以限定证据判断声明。
6. **呈现与导出**：展示原句、结论、理由和源码，输出 Markdown、HTML、JSON。

## 模块分工

- `src/vulngym_evidence/`：当前产品合同、提取、取证、运行调度、模型设置、本地 HTTP 服务与网页。
- `src/vulngym_agent/`：复用的底层工具、证据与模型适配基础，仍为当前实现的依赖。
- `scripts/start_desktop.py`：桌面启动入口，准备随包的教学 Git 对象并启动本地服务。
- `configs/evidence/`、`materials/`：公开教学输入与固定源码材料；不包含私人任务结果。

## 三种结论

| 结论 | 含义 |
|---|---|
| 证据支持 | 当前证据支持所核查的具体说法 |
| 与源码矛盾 | 当前源码与报告的具体说法存在冲突 |
| 证据不足 | 当前范围不足以确定，需要补充证据 |

结论以当前声明、源码版本和读取范围为边界。库函数的局部源码不能自动证明所有调用方和部署环境的行为。

## 案例与实际任务

完整教学流程展示保存的任务记录，不产生新的推理调用；源码引用核对可以不使用模型。正式报告的提取和语义复核使用用户配置的模型，两种路径在界面中分别标识。

## 存储

报告草稿位于当前标签页；最近任务索引属于当前浏览器；任务结果保存至本地服务输出目录。模型凭据默认仅本次服务使用，可选择受支持的系统凭据存储。模型服务收到待核查内容与必要源码证据。
