## 核心问题与真实场景

参与开源开发的学生和维护者收到漏洞报告后，要在报告、历史代码和背景资料之间反复查找。报告可能引用正确，却描述错误；也可能把缺少上下文误写成没有防护。AI 生成更多文字并不能自动解决这个查证任务。

本工具帮助开发者把报告里具体说法核对到指定版本源码。用户导入报告，AI 整理候选，用户确认后进入复核，最后获得逐条结论和可打开的依据。目标是减少审阅中的信息切换，让用户知道哪里一致、哪里矛盾、哪里还缺材料；尚未测量用户节省时间。

## 主要创意与当前 Demo

三步界面对应导入报告、确认内容、阅读结果。AI 候选保留原文位置，用户可以修改和补充，系统只审核用户确认的内容。结果将报告原句、中文解释、关键源码放在一起，可导出 JSON、Markdown、HTML。

教学演示基于公开 FastMCP 固定源码。报告声称参数没有编码，实际替换前已经编码并处理点号，输出与源码矛盾；报告声称调用方必然实施完整网络防护，但缺调用方材料，输出证据不足；引用位置确实存在，输出引用一致。三个结果来自同一真实任务，没有预置参考答案参与推理。

这是作者构造的教学报告，不是新发现漏洞或真实用户反馈。明确结论仅针对该条声明；引用一致不代表整个报告真实，证据不足不代表防护一定不存在。

## AI 模型、工具与实践方式

当前使用 DashScope 上的 qwen3.8-flash，北京地域、非思考模式。候选提取读取用户报告，将明确说法组织成结构化草稿，保留原文出处，不提前判定真假；漏提或缺字段时由用户补充确认。

取证工具读取固定 Commit 的源码、有限辅助定义及用户已提供的公告/补丁。主审模型结合这些证据解释声明，必要时增加反证复核。两个角色使用同一模型，复核不接收主审意见，不是两个独立模型的交叉验证。

程序负责合同与引用校验：模型选择真实源码行 ID，应用从实际窗口复制代码；检查声明归属、范围、置信度及判定状态。模型或输出错误保留为未完成，缺材料保留为不足，不自动重试。输入哈希、版本、模型用量与原始记录均可追溯。

## 技术路径与完成进度

报告与固定版本 → AI 候选 → 用户确认 → 只读源码取证 → 主审与条件复核 → 引用及判定校验 → 三类结果 → 证据阅读与报告导出。

本地 Python 网页与 CLI 共用核心；新增核心无第三方运行依赖，不运行目标项目或 PoC。用户配置密钥仅用于本地进程，提交材料不包含 Key。已实现六项首版模块，并支持同任务 URL 在刷新、服务重启后恢复。

公开多用户托管、历史任务浏览列表、新版网页批量任务尚未实现，各为 0%。按六项已实现加三项扩展计，未实现占 3/9；不是成熟度百分比。当前可运行本地 Demo，仍需负责人录制及托管视频、填写有效在读证明并正式报名。

## 已验证成果及实际边界

2026-10-06 当前版本 221 项软件测试通过。两个固定语义回归组分别为 11/11 和 15/15 与作者参考一致，调用或输出合同失败为 0。参考由开发 Agent 编写，非独立金标准，不能宣称泛化准确率 100%。原始失败历史保留，不把旧版本最好结果拼接成最新成绩。

三份报告提取出 9 条候选并逐条检查。现有 Edge 网页另完成新报告提取、用户确认、同任务三种结论、源码定位及导出内容核对，刷新和服务重启恢复通过。演示的两条语义候选由 AI 提取，一条引用由人工从同报告补充。安装包提供新虚拟环境和三个零模型控制项验证。

没有实测真实用户效率、第二台设备或任意报告整链路准确率。它是帮助人工复核具体声明的 AI 工具，不代替完整安全审计或证明漏洞已消除。

## 赛道适配、来源与后续空间

效率进化开放方向的价值在于把开发者的查证任务组织成可操作流程，AI 参与核心判断，源码提供可审阅依据。初赛展示已有功能和真实运行；若晋级，围绕初赛 Demo 在规定 48H 中开发可验证增量，优先改善引导、材料补全和任务管理。
