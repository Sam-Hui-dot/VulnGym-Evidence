# 3–5 分钟演示脚本

本脚本用于最终录屏。目标不是展示所有代码，而是在五分钟内证明：系统能运行、结论有证据、模型受
契约约束，并且参与者理解系统边界。

## 录制前准备

1. 打开 `SUBMISSION_OVERVIEW.md`、`docs/DESIGN_SUMMARY.md`、最终报告和 WSL 终端。
2. 关闭微信、邮件和浏览器通知，关闭所有 `.env`、账号和账单页面。
3. 终端进入仓库并清屏：

   ```bash
   cd /home/sam/rhinobird/VulnGym-Agent
   clear
   ```

4. 将终端字号调到 18–22，窗口宽度保证中文不换行。
5. 先试运行 `python3 scripts/verify_delivery.py`，确认显示 `DELIVERY CHECK: PASS`。
6. Windows 可用 `Win+Alt+R` 开始和结束录制；若游戏栏无法录桌面，使用 OBS 的“显示器采集”。建议
   1080p、30 FPS、系统声音关闭、麦克风开启。

## 分镜与台词

### 0:00–0:30 · 题目和一句话定位

画面：`SUBMISSION_OVERVIEW.md` 顶部。

台词：

> 我选择的是 VulnGym 实战 T1。VulnGym 的一条记录即使格式正确，漏洞入口、关键操作和链路仍可能与
> 真实源码不一致。我的系统是证据优先的验证 Agent：确定性工具负责找事实，模型负责语义判断，最后
> 给出逐字段、可追溯、允许证据不足的报告。

### 0:30–1:05 · 架构

画面：`docs/DESIGN_SUMMARY.md` 的架构图。

台词：

> 输入先经过 Schema、Git、源码、公告、补丁和 Trace 检查，形成 Evidence Packet 0.11。系统还能在
> 严格预算内解析一跳跨文件 helper，重名或歧义时弃权。Judge 对六个语义字段逐项判断；只有低置信、
> 证据冲突或高风险结果才值得追加 Critic。模型输出必须引用真实 evidence ID，并通过本地 JSON Schema
> 和语义契约；低置信 Critic 不能覆盖更高置信 Judge，最终再合成八字段报告。被审计代码只读，不运行
> 陌生项目或 PoC。

### 1:05–1:25 · 展示输入

画面：终端。运行下面的命令，脚本会先停在输入摘要：

```bash
bash scripts/run_recording_demo.sh --open
```

台词：

> 这是交给 Agent 的一条 WeKnora 候选记录。它声称漏洞入口、关键操作、Commit 和四个 Trace 节点都是
> 正确的。接下来让系统结合公告、源码和补丁逐项验证，而不是只检查 JSON 格式。

说完后按 Enter。

### 1:25–2:35 · 真实运行 Agent

画面：终端显示运行过程。

台词：

> 系统先检查输入和本地资源，再用只读 Git、源码、公告、Patch 和 Trace 工具整理证据，然后调用 Qwen
> 完成主审。这个录屏入口为了完整展示 Judge→Critic 闭环，会再做一次反证复核；常规批次也支持按风险
> 选择性触发 Critic。模型只收到结构化证据包，不接触 API Key；确定结论还必须引用真实证据编号。
> 完成后会同时输出证据、模型判断、八字段 JSONL 和人类可读报告。

说完后等待命令完成。正常情况下约需几十秒；不要重复运行或中途关闭终端。

### 2:35–3:05 · 展示本次新报告

画面：脚本先在终端打印八字段结果，然后自动打开刚生成的 `out/recording-demo/report.html`。

台词：

> 这是本次现场运行刚生成的结果。终端同时保留 Provider、模型、调用次数、Token 和耗时元数据，证明
> 这不是固定文本回放。系统没有因为路径和代码片段存在就全部判正确，而是结合生命周期
> 证据判断原记录把客户端构造位置误写成启动子进程，原 Trace 也漏了配置保存、重新读取和真正启动阶段。
> 报告逐字段列出结论、置信度、理由和证据，并在可以确定时给出建议修正。

### 3:05–3:30 · 评测与诚实边界

画面：回到 `SUBMISSION_OVERVIEW.md` 的结果摘要表。

台词：

> 同一个 DeepSeek 模型只看裸记录时检出 9/12 个预登记错误字段，加入证据工具后是 12/12；紧凑证据
> 又把 Token 降低约一半。冻结的 Blind v6 唯一运行是 62/64、错误检出 10/10。Final Blind 扩展到
> 五仓和三种语言，但受调用上限只完成四条。它们都是自建公开数据评测，不冒充官方隐藏集或专家 Gold。

### 3:30–3:45 · 批次系统性错误分析

画面：打开 `artifacts/final-blind-v1/systemic-analysis.md`。

台词：

> 单条报告之外，系统会自动汇总一批任务中的重复问题，并列出案例和改进建议。这里把它们称为需要复核
> 的重复信号，不把统计相关性冒充已经证明的根因。

### 3:45–4:15 · 工程化验证

画面：终端。运行：

```bash
python3 scripts/verify_delivery.py
```

台词：

> 自检会确认 134 项测试、91 项必需文件、固定演示、评测摘要、批次分析动态复算和敏感文件边界。
> 完整 Agent 可用一条 validate 命令运行，支持原子 checkpoint 和 resume；Prompt 有版本、哈希和
> 变更历史，AI Coding、人工决策和失败实验均有留痕。

### 4:15–4:35 · 结尾

画面：回到 `SUBMISSION_OVERVIEW.md`。

台词：

> 这个项目的目标不是做一个比通用模型更大的模型，而是把模型放进一条专门面向 VulnGym 的证据链，
> 让每个判断可复核、可替换、可复现，并在证据不足时主动弃权。当前结果不冒充官方隐藏集准确率，
> 但完整展示了 Agent 设计、工程实现和自我评估机制。
