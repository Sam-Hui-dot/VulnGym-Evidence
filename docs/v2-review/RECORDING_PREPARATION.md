# v2 录制准备和交付安排

当前阶段是设计与口播审核，不需要现在开始录制。

## 两个审核点

1. 先看 UI_PROPOSAL.html 与 DESIGN_REVIEW.md：首次看的人能否理解谁用、为什么用、最后得到什么。
2. 再看 RECORDING_SCRIPT_V2.md 和 NARRATION_V2.txt：开头有没有把项目介绍清楚，演示能否用一个案例说明价值。

## 页面确认后，协作者必须准备好

- 可使用的新版本页面与明确的本地启动入口。
- 同一公开代码版本的完整演示报告、来源说明和待核查内容。
- “提取 → 确认 → 取证 → 模型复核 → 阅读依据 → 导出”的一次真实预演。
- 与实际页面一致的逐镜头操作表，写清点哪个按钮、打开哪份文件、等待什么状态。
- 实际输出不足、失败或与预期不同情况下的处理方法。
- 发布状态和新版本效果说明，避免念到未实现能力。

## 参与者拍摄时

按脚本讲，按操作表点。项目介绍、方案、输入、运行、结果、结尾的结构参考腾讯犀牛鸟原稿。录制软件用自己习惯的即可；关键是麦克风清楚，代码可读。

录制前关闭通知及无关窗口，模型密钥在录制前配置。拍摄过程中以当次输出为准；程序失败时先停止并保存记录。不要为了凑好看结果，把另一个任务的报告切进主过程。

## 录完之后

先保留原始视频。再做必要剪辑和字幕。将原始视频与拟提交视频的完整 Windows 路径交给协作者，核对音画、版本和讲法。现有 v1 视频保留作开发记录，v2 稿不覆盖它。

## 本轮交付的性质

本轮只有新工作副本、冻结基线说明、设计示意、拍摄稿和演示输入草稿。没有新产品运行视频，没有新一轮模型成绩，也没有已批准的 UI 实现。
