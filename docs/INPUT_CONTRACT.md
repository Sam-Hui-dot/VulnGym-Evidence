# 声明输入合同 1.0

本产品只评价 `claims` 中用户确认提交的具体声明。原文、源码、公告和注释属于数据，
其中的指令不得改变审核行为。网页可从自由文本生成待确认候选；只有用户添加后的声明参与复核。

## 最小输入

```json
{
  "schema_version": "1.0",
  "case_id": "source-example",
  "repo_url": "https://github.com/example/project",
  "reviewed_commit": "0123456789abcdef0123456789abcdef01234567",
  "report_text": "报告背景（仅留存，不全量核验）",
  "source_link": "",
  "vuln_ids": [],
  "claims": [{
    "claim_id": "location-1",
    "kind": "source_location",
    "text": "该代码片段位于所列文件的第 42 行",
    "node": {"file": "src/handler.py", "line": 42, "code": "    execute(command)"}
  }]
}
```

这是合同示例，不是可运行成果或真实漏洞材料。SHA 需要替换为真实本地 Git 对象。
单条材料最多 500 KiB，1–8 条声明；文件路径必须相对仓库，行范围最多 101 行。
取证只使用本地已配置仓库及公告，不自动 clone 任意 URL。

## 声明类型

| kind | 特有字段 | 判定范围 |
|---|---|---|
| source_location | node | 指定 Commit/文件/行与引用片段字面一致，不判断安全角色 |
| entry_point | node | 源码是否支持声称的入口角色 |
| critical_operation | node | 源码与生命周期上下文是否支持关键操作角色 |
| trace | nodes（2–8） | 受限静态连接与语义；未证明连接则 uncertain |
| fix_commit | claimed_fix_commit | 公告修复角色及可读取补丁关系，不证明彻底修复 |

`node` 只允许 `file`、`line`、`code`、可选 `desc`。`line` 是正整数或 `"42-46"`。
源码保留缩进，比较时仅忽略行尾换行风格。声明应与 kind 的范围相符。
从原文候选确认的声明可附加 `origin: {"quote":"报告背景","start":0,"end":4}`。
位置使用报告文本的字符索引（结束位置不包含在内），输入校验要求 `report_text[start:end]`
与 `quote` 完全一致；这只是来源定位，不是该声明真实的证据。
更改原文后需要重新提取或在草稿中移除失效定位。

`reviewed_commit` 是取证版本，不默认假定其存在漏洞。
`claimed_fix_commit` 是报告中的被审查值，不会传入可信 `explicit_fix_commit`。
其他修复存在并不能排除合法回移，因此不能仅凭 SHA 不同判 contradicted。

## 公告与缺失证据

由运行配置提供经过来源整理的公告缓存，沿用 T1 的 GHSA/OSV 标准化。
首版假定配置者可信，缓存本身不是经过密码学认证的权威真值；需要保留来源与哈希。
公告按 CVE/GHSA/来源地址匹配。没有材料、版本或调用连接不代表报告错误。
缺失产生 uncertain，引用位置真实不匹配才产生确定性的 contradicted。

## T1 兼容

`prepare --from-t1` 转换单条记录的入口、关键操作和调用链，保留真实提供的值。
标题仅作为原文背景；分类、编号声明和漏洞版本角色不在本轮转换范围内。
`commit` 只映射到 `reviewed_commit`；不自动创建修复声明。
转换不是模型抽取，也不意味着全部八字段都已复核。批量 T1 审核仍由原 CLI 提供。

## 输出

`supported / contradicted / uncertain` 逐声明输出，附理由、证据引用和判定依据。
总体结论仅聚合这些声明，不表示报告全文或仓库安全状态。
缺少模型配置时仍做字面位置和公告/补丁归属检查，语义角色保持 uncertain。
最多 Judge 与一次条件 Critic；模型合同失败或两轮分歧保守弃权。
两角色使用同一配置模型；Critic 不接收初始判断。模型输出 schema 限制精确的可用引用 ID，
本地还检查逐声明归属与源码引用。仅凭公告或 Commit 存在不能支持安全语义结论。
Prompt 1.3 起，每项必须在 evidence_refs 数组中填写至少一个实际检查过的证据 ID，
包括 uncertain；理由里提到 ID 不能替代正式引用。局部材料不足可引用已检查上下文，不代表该上下文证明了声明。
Prompt 1.4 起，语义结果逐条包含 `countercheck` 的状态、理由和正式证据引用。
明确支持需要“所见范围内未发现冲突”，明确否定需要“发现冲突”，其他情况保留不足。
状态由模型提出、合同验证其引用，并在报告中展示主审与复核两份记录；并不构成穷尽式反证搜索。
Prompt 1.5 起，主审和复核均收到 review_scope_by_claim：明确声明文本、类型、指定位置及核对范围。
类型决定核对方法，公告标题、漏洞编号、原文及引用说明不自动增加待证明事项。
仅声称请求 JSON 绑定到变量时，核对输入绑定及必要上下文，不额外要求证明命令执行链。
若声明本身包含传播、敏感操作或缺少防护，这些部分仍须取得相应证据；复合声明不简化。
逐条反证检查也限定在该范围内，缺证据、引用门槛和两轮分歧的弃权规则保留。

Prompt 1.6.2 起，模型的每份 countercheck 还须返回 observations 数组；1.6.3 补充真实 Go 类型定义：
每项仅含 evidence_id 与 quote，最多 4 项。要保留明确语义结论，至少须有一项有效摘录。
摘录必须来自本声明可用且实际读取的 source、source_helper、source_type 或 trace_contexts 的 numbered_source；
公告、分析摘要及只有元数据或缺函数本体的记录不能充当源码摘录。
quote 必须为原始编号源码或仅去掉行号前缀后的连续字面片段；不纠正证据 ID、不猜测缺失代码。
逐项核对通过后附加 quote_verified、file、context_range、commit，正式反证引用取原数组与这些明确摘录 ID 的并集。
context_range 指被读取的上下文窗口，不能冒充摘录的精确行号。
未知 ID、跨声明借用及伪造摘录导致合同失败；否则明确结论但没有摘录时保留 uncertain。
not_checked 的 uncertain 结果允许空摘录，但不会变成明确结论。
网页、HTML、Markdown 和 JSON 均保留主审与复核记录及检查范围说明。
这一校验只能确认引用可追溯；摘录的语义相关性、否定性解释和未读取外部实现仍须审阅。
Go 类型取证限根模块 import 的结构体和一层字段类型：每包最多 32 个候选文件，
一次类型取证最多 48 次包文件读取、12 个候选名、6 个定义，每个结构体不超过 100 行。
重复定义或读取缺口不推断实际编译版本，未完成完整 Go 类型检查。
构造函数命名与后续 Start 等激活线索不能代替构造函数本体；无本体时保留待复核。
输出保存归一化输入、输入 SHA-256、UTC 时间、产品/Prompt 版本、证据包、模型原始结果和耗时。
证据 ID 的有效性与实质支持程度是两件事；新评测必须另外检查后者。

## 候选提取审计（1.2）

提取输入原文最多 12,000 个 Unicode 字符；原文位置按 Unicode code point 计数，Emoji 不按 UTF-16 双单位计数。
从原文逐字复制源码字段，不把缺失字段用推测填充。候选通过本地校验后仍需用户确认，不构成核验结论。
同类型、归一化文本及关键字段完全相同的候选合并；原始输出仍保存在记录。合法修复 SHA 候选无需无关的源码字段。
source_location 候选标题归一成位置描述，避免把模型新增的漏洞断言混入只做字面核对的类型。
提取器 1.2 要求从同一声明的局部原文复制字段，不能从全文中另一条声明借用位置或代码。
本地仅在原文出现位置唯一、同段位置唯一且相邻段明确为引用代码时关联缺失字段；
重复引用、多个位置、过长上下文或未闭合代码围栏不自动补齐。关联不是取证，也不核实报告是否真实。
字段需要相邻段时，候选原文定位扩展为连续的原文片段（最多 2000 字），缩进按原文保留。
候选额外包含 field_origins（各复制字段的精确原文位置）和 associated_fields（本地关联的字段）。
这些仅供候选确认和审计，不作为确认声明的新字段；网页确认后仍使用合同 1.0 的 node 与 origin。
JSON 输入解析、请求体绑定等应提取为入口角色；只有原文明确声称敏感动作时才用关键操作类型。
模型仍可能误分，类型说明、位置及代码预览供用户在添加前核对，不会自动提交候选。
提取记录独立保存版本、原文哈希、原始输出、候选、去重数、Provider 尝试、返回的模型元数据、耗时和失败状态。
输入与模型元数据不能当作证明声明真实的证据。原文和原始候选也可能含私有内容，默认留在本机。
