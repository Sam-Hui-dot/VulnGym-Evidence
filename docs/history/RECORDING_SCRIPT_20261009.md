# 录制脚本：0.2.0 照着点击版

作品：VulnGym Evidence：漏洞报告证据复核智能体。成片 180 秒，9 段；口播框可分别复制到字幕与 AI 配音工具。

这条路线无需模型 Key：先展示已保存的真实 AI 结果，再亲自运行一次源码引用核对。画面与口播会明确区分两者。实时 AI 提取、语义复核仍在完整本机版提供。

## 录制前做完这四步

1. 打开新版 Source 文件夹，双击 start-evidence.cmd。
2. 在终端输入 1，按回车，保留终端；使用它自动打开的 Edge 页面。
3. 在 Edge 按 F11，进入全屏。不要录终端、Key 控制台或账单页。
4. 录屏设为 1080p、30fps。每段单独录，停留时间按下文执行，最后按顺序拼接。

以下任何按钮找不到，或页面出现错误：停在当前画面，截图给我，不要自行换流程。

```text
漏洞报告写得详细，维护者仍要回到代码里查证：它描述的行为，真的发生在这个版本吗？VulnGym Evidence 面向开源维护者和开发者，把报告原句、复核理由与源码放在一起，帮助逐条核对。
```

## 03｜为什么说报告与源码矛盾

成片 00:35—01:00，25 秒。

**录什么：**第一条“参数编码”结果，右侧第 214、215 行。

**只做这些操作：**

1. 开始录这一段。
2. 点击左侧第一张“参数编码”卡片中间。
3. 鼠标指向右侧黄色高亮的第 214 行，停 8 秒。
4. 鼠标指向下一行第 215 行，停 5 秒。
5. 鼠标移到上方复核理由，保持到本段结束。不要翻源码页。

**字幕／AI 配音：**

```text
报告声称路径参数没有编码。但源码在第 214 行先进行 URL 编码，并处理点号，第 215 行才替换参数。因此，这条说法与代码矛盾。原句、解释和关键行同时显示，维护者可以直接检查判断依据。
```

## 05｜证据不足怎样帮助后续调查

成片 01:15—01:40，25 秒。

**录什么：**第二条“网络防护”，理由、源码与黄色“待补证据”区。

**只做这些操作：**

1. 开始录这一段。
2. 点击左侧第二张“网络防护”卡片中间。
3. 鼠标移到右侧理由，停 8 秒。
4. 鼠标移到下方黄色“待补证据”区，停 5 秒。
5. 点击右下“复核详情”。
6. 保持可读详情 7 秒，点击窗口右上角 × 关闭。

**字幕／AI 配音：**

```text

```

## 06｜亲自运行一次引用核对

成片 01:40—02:05，25 秒。

**录什么：**进入确认页，核查项与报告原句，再生成本次结果。

**只做这些操作：**

1. 开始录这一段。
2. 点击页面右下“亲自运行同一报告”。
3. 在首页左侧卡片下方，点击“运行引用核对（无需 Key）”。
4. 看到“确认要核对的内容”，点击右侧“1. 源码位置”卡片正文中间。不要点右上小勾选框。
5. 左侧报告原句停 5 秒。
6. 点击右下蓝色“确认并复核 1 项 →”。
7. 等出现“引用一致”，保持到本段结束。

**字幕／AI 配音：**

```text
再亲自运行一次无需 Key 的引用核对。先确认报告原句和文件位置，然后读取随包提供的固定版本源码。这个新任务得到引用一致：它确认引用对应代码。对代码行为和完整防护的解释，则需要分别复核。
```

## 剪辑与材料对应

- 本脚本拍的是已保存真实 AI 结果加本次引用核对；字幕不能写“刚刚实时生成三条 AI 判断”。
- 如评审需要实时 AI 提取与语义复核，再使用模式 2 单独录制一个新任务；具体操作以该任务实际候选和结果为准，当前稿不拼接到那次任务后面。
- 主视频可用于展示同一作品；三个赛事的介绍文档、提交字段分别填写。
- 这份 Markdown 是操作与配音稿，没有制作自动配音成片。
