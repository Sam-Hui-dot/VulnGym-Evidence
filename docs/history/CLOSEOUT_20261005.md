# 本轮方向、验收与交付记录

更新：2026-10-05。原腾讯 T1、冻结 v1 均保留；本文和本地源码快照是审核材料，不是已提交的参赛作品。

## 方向如何变化

原 T1 面向指定任务的结构化材料核对，已有版本、源码读取、来源和报告等工程基础。本次复用这些基础，新增报告原文提取、用户确认、逐条声明核查、源码上下文和语义解释，以及供人阅读的三步网页。

合理的扩展是让输入和用户入口更通用，同时让每次核查保持边界：一个已准备的 Git 仓库、指定版本、用户确认的具体原句和可读取的源码。不是自动评判任意项目是否安全，也没有实现完整漏洞复现、全仓库污点分析或任意远程仓库自动接入。比赛没有要求我们无限扩大验证范围；本轮停止加功能。

三个比赛可复用工程核心。上海突出开源开发工具与可复现代码；天猫突出 AI 实际参与和清晰的用户工作流；openJiuwen 的创意材料可围绕 Coding 场景。跨赛提交权利和三方共享条款未作无条件认可，名称和报名都未自动改动。

## 本轮具体改动

1. 约束模型保留声明主语，局部库函数证据不能替代未读取的业务调用方或部署配置。
2. 模型选择真实源码行 ID，程序映射其证据窗口并逐字复制，不由模型抄写源码或拼凑行号。
3. 结论和反证状态改为一项合法组合；引用真实性、归属、置信度和独立复核门槛保留。
4. 为本轮在线验收添加共享预算账本，在请求前预留额度；超时和未知用量不会自动退回或重试。
5. 更新实现状态、评测和录像脚本，保留历史失败；未自动制作新视频。

## 怎么审核

先读本页，确认工具定位是否合适；再看本轮 HTTP 任务导出的 report.html 和录像脚本。HTML 是实际保存的结果，不冒充正在运行的网页。查看模型意见、源码引用和复核状态时，要区分“缺少业务材料”和“调用/输出未完成”。

旧 8772 服务未在本轮更新；它可能仍加载旧版。最新 1.8.2 源码已冻结为审核快照，但最新完整线上工作流仍待验收，不是正式发布包。

## 交赛前还缺什么

- 工程：最新协议一次完整主审/复核与同一录像案例预演；本轮不再扩大功能或无限在线调参。
- 材料：确定最终名称与上海报名是否更新；据实际功能定稿介绍 PDF；由本人按脚本录制视频，提供可访问的视频链接。
- 发布：公开完整可运行的仓库和对应版本，检查来源许可与链接访问；由本人完成报名、上传或邮件提交。

同学试用是可选体验补充，不是当前已知统一必交项。最终录制和仓库发布前仍需完成上面的具体检查，不能把“本地测试通过”表述为“参赛提交已经完成”。
