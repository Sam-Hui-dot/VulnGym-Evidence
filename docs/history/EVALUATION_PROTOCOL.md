# 声明级开发对照评测 v1 · 2026-10-03

目的：检查新版在 WeKnora 之外的新增声明上，取证流程相较只提供报告片段能带来什么，以及仍会产生什么错误。
这是作者阅读源码后构造并标注的开发对照，不是自然报告的代表性样本，也不是独立专家盲测。
ADK、FastMCP、Flowise 的仓库或其他漏洞曾出现在旧 T1 工作中，不能宣称仓库完全未见；模型训练数据污染未知。

## 冻结与执行

先固定 12 个单声明输入、参考判断、理由、Git 版本、文件 SHA-256 及支持片段，再冻结实现快照和哈希。
9 项语义判断（支持/矛盾/不足各 3）与 3 项工程控制（正确引用/错误引用/缺版本各 1）分层统计。
声明由作者新写或故意变造，并非发现新漏洞；不执行目标项目代码或实际攻击。
参考答案依据完整所需源码和已知材料范围，由开发代理审阅，尚无独立人类复核。

报告组：同一个 Qwen 模型，只拿输入声明和报告中引用的片段，不访问 Git。片段明确标为未经仓库核验。
取证组：相同输入，经现有工作流读取指定 Git 版本、邻近源码、helper、生命周期等证据后判断。
本轮不提供公告缓存，不依赖既有漏洞标签来决定答案。
双方都最多一次主审、一次条件复核：主审给出明确结论时才调用 Critic，后者不接收主审意见。
双方使用同一个基础审核提示、输出合同、置信度和反证门槛；报告组增加其无仓库访问的事实说明。
报告组没有取证组的字面比较、生命周期门槛与 Git 缺失判定；这是整体工作流比较，不能隔离证明某个组件或模型更好。
相邻样例交替两组运行顺序；单次运行，无自动重试或按好坏重跑，无统计显著性结论。
每次请求原文、输出、实际模型、Token、耗时均落盘；任何请求不得包含参考标签、理由或另一组答案。
冻结后完整首轮结束前不改审核代码、提示词或参考答案。失败保留，不能当作正确弃权。

## 指标及分母

- 标签匹配：支持、矛盾、不足三类与参考一致的数量 / 全部样例。
- 明确判断覆盖：输出支持或矛盾 / 全部样例；明确判断正确数另报，防止全部弃权获得表面安全。
- 错误接受：参考矛盾却输出支持 / 参考矛盾总数。
- 错误否定：参考支持却输出矛盾；材料不足却强行给支持或矛盾另计。
- 弃权和调用/合同错误分别计数；错误分母保留。
- 各组实际调用数、API 返回 Token、各样例端到端耗时累加。调用数可因条件复核和确定性检查不同而不同。
- 人工检查模型理由是否超出证据；标签匹配不能替代实质引用质量。

只给报告片段的一组信息较少，因此差异同时反映仓库访问、取证、确定性规则和复核的整体价值。
不得将其写成“胜过有工具的 ChatGPT/其他 agent”，也不得由 12 个相关样例推算泛化准确率或获奖概率。
