# 代码佐证 v2：录制脚本

本稿对应 2026-10-04 的真实三步界面。视频由项目作者录制，建议控制在 2 分 50 秒至 3 分钟。先审核网页和下面的口播，再正式拍摄。

## 录制前

1. 打开本地应用 `http://127.0.0.1:8772/`，保留项目、版本、三个步骤和底部操作按钮。
2. 使用正常浏览器缩放。先确认自己的录制窗口里不需要上下滚动；长报告和长源码使用页面内的“上一页 / 下一页”。
3. 先读本文件，排练候选编辑和源码详情操作。排练结果与正式录制结果分开保留。
4. 正式录制前重启 v2 服务，清空本次服务的提取缓存，保留磁盘已有结果。打开首页，点击“加载样例”。不要删除旧结果目录。
5. 从加载报告一直录到生成新结果。等待模型的片段可以剪短，加字幕“模型处理等待已剪短”。保留提交、进度、结果出现的连续关系。
6. 不录 API Key 的输入过程。画面关闭与演示无关的个人标签页。

源码：PrefectHQ/fastmcp，固定版本 `40bdfb6b1de0ce30609ee9ba5bb95ecd04a9fb71`。报告是作者根据公开源码编写的教学材料。演示三条声明，不宣称发现了新的漏洞。

## 两种结尾

上海：代码佐证 将报告确认、源码取证和反证复核组织成可复现的开源工具，帮助开发者留下清楚的审阅依据。

天猫：代码佐证 把 AI 用在报告整理和证据复核这两个实际环节，帮助开发者从一段描述走到可以继续处理的审阅结果。

## 正式拍摄遇到异常

- 提取遗漏或简化声明：在确认页据原文补齐，如实展示用户确认。
- 输出“复核未完成”：保留失败记录，处理原因后另建一次新任务；不要把这一状态讲成证据不足。
- 新结果与排练不同：按实际结果说明；检查证据后再决定是否需要修复，不换用旧结果冒充现场输出。
- 服务连接中断：先恢复已有任务，避免重复发起模型调用。

审核通过后再录制。上海的作品文档、源码链接及两赛提交介绍在新界面最终确认后同步更新。
