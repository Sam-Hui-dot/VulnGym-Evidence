# VulnGym Evidence 新版演示脚本

目标时长约 3 分钟，作为制作安排；实际上传时长限制以报名页面为准。腾讯 T1 旧脚本另存为 DEMO_SCRIPT_T1.md。

## 录制前

使用已检查的当前服务或按 QUICKSTART 启动相同版本，准备公开固定版本样例。关闭密钥、账号账单、通知和私聊。展示真实新运行；保存结果回放须明确标注，不把回放当在线运行。

## 0:00-0:25：真实问题

画面：产品标题及报告输入。
台词：开发者收到漏洞报告，需要回到正确的代码版本逐条查证。这份报告引用的代码是否真实，声称的入口或关键操作是否得到实现支持？VulnGym Evidence 把这项工作组织成有证据、可复查的流程。

## 0:25-1:00：候选与用户确认

画面：原文、候选卡片、来源位置、补齐与添加。
台词：AI 先提取待核验候选，并保留原文位置。我确认声明和引用代码后再加入复核。系统只检查这些明确提交的内容，抽取结果本身不是证据。

## 1:00-1:45：真实取证与模型复核

画面：确认提交、实际阶段事件。
台词：系统读取指定 Git 版本的源码和必要上下文。字面位置由程序核对，安全角色由模型主审与反证复核。两角色用同一个配置模型，复核不接收主审意见。缺材料、合同失败或双方分歧都可以保留为不足。

等待仅说明实际步骤，不伪造进度；模型失败时保留失败，不连续重跑挑结果。

## 1:45-2:25：结论、源码与反证摘录

画面：逐条结果、证据跳转、展开反证依据摘录、完整报告。
台词：每条判断都能回到源码。反证记录包含实际源码摘录，程序会核对它是否出现在所引用的窗口中。摘录真实并不保证解释全对，未读取的外部实现和运行配置仍需另行核查。

## 2:25-2:45：保存与恢复

画面：报告导出，刷新同一任务。
台词：结果可以导出 JSON、Markdown 和 HTML。同一个服务会话刷新仍可恢复任务；重启后可以打开已经保存的报告文件，网页历史浏览尚未实现。

## 2:45-3:10：效果与后续

画面：小规模开发对照表及功能状态。
台词：已有 9 条语义声明的同模型开发对照，与作者参考一致的结果从只看报告的 4/9 到取证流程的 7/9，2 条输出失败仍在分母里。这是小样本开发检查。当前首版面向本机的逐声明复核，后续完善历史任务与有界批量入口。

正式视频链接和发行版本在提交前加入总览；本脚本不证明视频已经录制。
