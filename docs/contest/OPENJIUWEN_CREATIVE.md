# VulnGym Evidence：漏洞报告证据复核智能体

openJiuwen 智能体创新大赛 | Coding 方向创意材料
负责人：项目作者 |  | 2026-10-06

## 目标用户与问题

开源维护者和学生开发者收到漏洞报告后，需要核对版本、代码引用和行为解释。AI 报告可能写得完整，但引用真实不等于语义成立；局部源码也不足以说明整个部署的防护。本项目将查证过程组织成有工具、有证据、有人工确认的 Agent 工作流。

## 创意与应用场景

用户提供报告、代码仓库和固定版本，AI 提取候选内容，用户确认后工具读取源码，模型主审与条件复核分别检查具体说法，给出支持、矛盾或不足，并展示原文、中文原因和源码。适用于开源问题单初审、安全课程及开发团队报告复查，不替代完整安全审计。

教学 Demo 使用真实 FastMCP 固定源码：编码描述可被相邻源码反驳；外部调用方防护因缺材料保留不足；引用位置一致单独核对。这将引用准确性、行为语义和证据范围分开表达，而非输出一个整体“安全/不安全”。

## Agent 技术方案

本地 Python 网页与 CLI → 结构化声明与来源 → 只读 Git/source 工具 → Qwen 主审 → 条件反证复核 → 输出与引用合同校验 → 可阅读审阅报告。主审/复核是同一模型不同角色，复核不接收主审答案。

模型选择源码行 ID，程序从实际证据复制摘录，防止伪造或错归属引用；对未读调用方与配置不作全局推断。保留输入哈希、版本、实际调用和失败记录，不执行目标代码或 PoC。当前实现使用自有 Python 工作流；尚未接入 JiuwenSwarm，公告将其列为推荐平台，不能虚构已完成集成。

## 当前基础与验证

已有六项首版能力：输入确认、AI 候选、固定源码取证、逐声明复核、证据阅读、报告与同任务恢复。当前 0.1.0 / claims-judge-1.8.2，qwen3.8-flash。221 项软件测试通过，两个作者参考回归组分别 11/11、15/15 一致；不声称独立泛化准确率。真实 Edge 新任务完成三种结果、源码定位、报告内容及重启恢复。

源码、wheel、固定演示材料与复现记录已准备。当前没有公开多用户服务、历史列表或网页批量任务；代码仓库与视频公开链接、报名仍由负责人完成。后续若进入 Demo 开发，可结合赛事平台提供的真实工具能力，优先增加可追踪任务管理与材料补全，范围取决于实际接口及赛事要求。
